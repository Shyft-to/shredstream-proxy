- Tag: `kfan_df-off`.
- **Geyserbench (operator): ~1 ms added latency again**, the same as
  chapter 6. Matches the explanation there: one CPU sends ~23 copies per
  shred serially (~32 µs per shred), so in a burst of a FEC set the
  shreds the node needs leave up to ~1 ms late. The probe cannot show
  this under kfan (its arrival stamp is taken when the busy CPU picks a
  shred up), so neither the box probe nor `fec-ready.py` is a fair
  measure of kfan; geyserbench is.
